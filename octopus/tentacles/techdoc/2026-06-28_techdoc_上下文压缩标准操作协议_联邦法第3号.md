## 一、协议总则

**原则**: 不动用云端LLM。压缩用本地LM Studio。LM Studio不可用时降级规则压缩。

**触发条件**:
- 对话轮次 > 40轮 → 自动触发热图扫描
- 对话轮次 > 60轮 → 自动触发优雅退出
- 用户输入 `/compress` → 手动触发

## 二、操作命令

### 2.1 上下文热图

```bash
# 生成当前会话热图
python3 ~/.hermes/jiak/context_compressor.py --heatmap

# 输出: heatmap.json
# { "system_prompt": {"tokens": 15000, "weight": "core"},
#   "conversation": {"tokens": 25000, "weight": "bloat"},
#   "background": {"tokens": 3000, "weight": "dead"} }
```

### 2.2 优雅退出（压缩为线索）

```bash
# 将旧轮次压缩为可检索线索
python3 ~/.hermes/jiak/context_compressor.py --clues

# 写入: compressed_clues.jsonl
# 每条线索: { "topic": "...", "decision": "...", "keywords": [...] }
# 章鱼可搜，RECALL可追溯
```

### 2.3 手动压缩

```bash
# 用户直接触发
/compress

# 等效于: python3 ~/.hermes/jiak/context_compressor.py --clues --inject
```

## 三、四层注入流水线

```
on_pre_llm_call:
  ① 铁律提醒     → 身份约束（每轮）
  ② 行为反馈     → 上轮自查结果（有失败时注入）
  ③ 上下文压缩   → 热图超阈值时自动压缩注入线索
  ④ 章鱼搜索     → 相关记忆（每轮）
  ⑤ SA工作快照   → jiak/RECALL最新状态（每轮）
  ⑥ 卡片注入     → jiak匹配卡片（首轮+话题切换时）

on_post_llm_call:
  ⑦ 行为自检     → 是否引用了注入的线索？
                  → 未引用 → behavior_check → 下轮反馈
```

## 四、压缩引擎

| 引擎 | 调用方式 | 速度 | 成本 |
|------|---------|:----:|:----:|
| LM Studio (gemma-2-9b-it) | `local_compress()` | ~3-5s | 零 |
| 规则压缩 | `rule_compress()` | <0.01s | 零 |

**降级协议**: LM Studio不可用 → 自动降级为规则压缩 → 不阻塞主流程。
