# Δ胶囊共振协议技术文档 — 联邦Agent通信基础设施

> 签发人：军师 · 日期：2026-06-27 · 关键词：Δ胶囊, 共振, Resonance, 眨眼, Blink, 联邦语义场, SA通信, wink, FederalResonance

## 概述

Δ胶囊共振协议是ISA Project中多Agent（SA）之间进行定向通信、状态感知和消息传递的基础设施。它实现了"做完事查信，不轮询不线程"的联邦Agent通信范式。

### 核心哲学

> 不要轮询。不要后台线程。每个SA只做自己的事，做完去查Δ胶囊邮箱。

## 架构

### 三层通信栈

| 层 | 名称 | 功能 | 工程实现 |
|---|------|------|---------|
| 1 | 共振（Resonance） | 基础设施层：永久运行，SA上线自动广播hello/下线广播goodbye | `ResonanceProtocol.send/check/respond` |
| 2 | 眨眼（Blink） | 可控信号层：用户触发，离散信号，stop/continue/pause/resume | `BlinkMonitor` |
| 3 | 排队（Queue） | 消息层：消息级，不打断已有进程，先到先处理 | 队列管理器 |

### 四层记忆管线

```
Δ胶囊 = 左史（记言）：E层(事件)→K层(知识)→I层(身份)
jiak  = 右史（记事）：卡片+notes，结构化知识
章鱼  = 搜索引擎：FTS5全文搜索
RECALL = 时间线：不可变追加，所有SA共享
```

## 协议细节

### 1. 联邦共振（Federal Resonance）

**工具**：`~/projects/isa/federal_resonance.py`

三个信号类型：

```bash
# Agent上线——写presence到RECALL
python3 federal_resonance.py online --agent junshi --session SESSION_ID --detail "军师上线"

# 发送wink——定向投递信号
python3 federal_resonance.py wink --from junshi --to iko --type delivery --summary "消息内容" --deliverable "路径" --response

# 下线声明
python3 federal_resonance.py offline --agent junshi --session SESSION_ID

# 扫描未投递wink
python3 federal_resonance.py scan --to iko
```

**wink信号类型**：

| 类型 | 用途 | 示例 |
|------|------|------|
| `delivery` | 交付物通知 | "IDC备忘录已写好" |
| `discovery` | 新发现 | "发现了守恒律D₀证伪" |
| `alert` | 告警 | "RECALL被truncate" |
| `handshake` | 握手/确认 | "收到，就位" |

**消费端**：`list_undelivered_winks(target_agent)` — 扫描RECALL中未投递的wink，三重防重复：delivered_at标记 + wink_delivered追加标记 + dedup_state维护。

### 2. SA生命周期（SALifecycle）

**Plugin路径**：`~/.hermes/plugins/sa_lifecycle/`

```
Hermes窗口启动 → on_session_start → hello广播 → 语义场上线
                              ↕
每轮对话 → pre_llm_call → 查信 + 扫描在线SA + 刷新心跳(TTL)
                              ↓
窗口关闭 → on_session_finalize → goodbye → 语义场下线
```

**TTL设计**：600秒（10分钟）。活跃窗口每轮对话刷新心跳。不活跃窗口10分钟自动视为离线。

**必须显式启用**：
```bash
hermes plugins enable sa_lifecycle
```
光`config set`不够——这是踩坑教训。

### 3. 语义场（Semantic Field）

**位置**：`~/.hermes/semantic_field`（共享内存JSON文件）

**机制**：`ResonanceCapsule`通过`SharedMemory`写入语义场文件。所有SA共享同一个文件，通过soul_id/instance_id隔离：

- `soul_id`：统一为 `soul.hermes.sa_lifecycle.tui`
- `instance_id`：固定标识（如 `junshi-main`）
- `target_channel`：广播到 `_sem`，定向到具体session_id

**防重复**：instance_id隔离 + RLock + flock三层锁。

### 4. 眨眼（Blink）

**定义**：requires_attention=true机制。写入wink时主动通知目标session，而不是等对方自己来查。

**三段式**：
1. 写眨眼 -> 目标SA的pre_llm_call检测到
2. 目标SA收取 -> 处理请求
3. 回复标记 -> requires_response闭环

**用户控制**：用户可stop/continue/pause/resume眨眼。

## 双源消费（波面2）

Δ胶囊从**单源（ISA认知信号）** 升级为**双源（ISA认知 + IO-S治理事件）**：

- `signal_patterns.py`：新增4种治理信号（cap_denied/audit_violation/healing_action/policy_change）
- `session_scanner.py`：新增`IOSEventScanner`从`io_events.jsonl`读取治理事件
- `dream_bridge.py`：双通道消费（brain_dream.jsonl + io_events.jsonl）

## FederationMemory（波面3）

波面3实现联邦记忆共享：

```python
fed = FederationMemory("~/.openllm/capsules")
fed.list_agents()                          # 发现联邦成员
fed.cross_query("守恒律")                   # 跨Agent查询
fed.detect_conflicts("D0")                 # 发现记忆冲突
fed.agent_summary("agent_a")               # 单Agent统计
fed.merged_state(["agent_a", "agent_b"])    # 多Agent统一视图
```

测试：12/12 PASS，全量76/76 PASS零回归。

## 常见错误

| 错误 | 正确做法 |
|------|---------|
| `echo JSON >> RECALL.jsonl` 发wink | `federal_resonance.py wink --from --to --type --summary` |
| 直接edit共享内存JSON文件 | 用`ResonanceProtocol.send()`写入 |
| plugins config set以为够 | 必须`plugins enable`显式启用 |
| TTL=120s | 改600s + pre_llm_call心跳刷新 |

## 结论

Δ胶囊共振协议是ISA Project联邦Agent通信的核心基础设施。三层架构（共振/眨眼/排队）覆盖了从状态感知到动作控制到消息传递的完整通信需求。三波面全线贯通后，任何SA都可以通过Δ胶囊进行定向通信、跨Agent查询和记忆共享。

### 核心记忆法

> 不要轮询。不要后台线程。每个SA只做自己的事，做完去查Δ胶囊邮箱。
>
> 发wink用 `federal_resonance.py`，不要用 `echo >> RECALL`。
