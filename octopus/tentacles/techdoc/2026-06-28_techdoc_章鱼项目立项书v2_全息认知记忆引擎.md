## 一、章鱼是什么

章鱼不是搜索引擎。章鱼是**Agent的工作记忆检索系统**——搜的是用户的全部数字资产：对话记录、知识笔记、决策日志、代码、文档、媒体文件、一切本地文件、外部公共知识。

与Google和Perplexity的核心差异：

| | Google | Perplexity | **章鱼** |
|---|--------|-----------|---------|
| 一句话 | 世界上有什么 | 关于X最值得知道的是什么 | **关于X我经历过什么——以及世界上关于X的最新东西和我有什么关系** |
| 数据域 | 全网公开 | 公开网络+实时 | **内外打穿——公共知识+个人经验共振** |
| 核心机制 | 倒排索引+PageRank | 实时搜索+LLM综合 | **割裂搜索+内外共鸣** |
| 不可替代 | 规模(百亿页面) | 给答案+归因 | **深度个人认知+内外共鸣+因果链** |

## 二、终极形态

**局部记忆图 + 经验回溯 + 认知关联**

```
核心能力：
├─ 局部记忆图：同一主题跨session连接——记忆网非时间线
├─ 经验回溯："为什么选A"→回溯到决策因果链
├─ 认知关联：A话题→B话题→C话题的推理链
├─ 内外共鸣：外部结果×内部经验→只属于你的回答
├─ 自动触发：Agent回答前自动关联旧经验
└─ 遗忘曲线：什么该记住、什么该淡化、什么该遗忘
```

### 终极场景

用户搜"2026年AI顶会关于记忆系统的最新论文"——

```
Google    → 100篇论文的链接
Perplexity → 5篇论文的摘要
章鱼终极 → "这篇论文的图2和你三个月前的Δ胶囊实验结果一致。
            同时它的方法学缺陷与你的守恒律研究有关。
            看这个——你的实验设计.docx在I盘第3节。"
```

## 三、八触须文档系统（搜索优先级）

章鱼搜什么——按优先级排序：

| # | 触须 | 文件名前缀 | 内容 |
|:--:|:----:|:---------:|------|
| 1 | 备忘录 | `memo` | 阶段性成果总结、架构说明、系统设计 |
| 2 | PAL | `pal` | 计划清单、任务分解、优先级 |
| 3 | 研究分析 | `analysis` | 投喂资料解析、深度分析、对比研究、评估可行性 |
| 4 | 情报简报 | `intel` | 情报搜集、竞品动态、行业趋势、外部信号 |
| 5 | 执行报告 | `execution` | 任务完成情况、代码变更、测试结果、故障排查 |
| 6 | 会议纪要 | `meeting` | 七神启示合议、多Agent合议、讨论要点、待办、分歧 |
| 7 | 技术文档 | `techdoc` | 联邦法、协议标准、API说明、产品说明、配置指南 |
| 8 | 决策记录 | `lesson` | 踩坑记录、最佳实践、复盘、要求记住的教训 |

**搜索策略**：先八触须文档（优先）→ 再SESSION（第二）→ 其余文档（章鱼当然也搜）。八文档和SESSION并列，必须都搜。

## 四、核心哲学

### 上下文管理公式v2

> **索引全·线索精·捞回快·读得透=完整回忆**

| 要素 | 做什么 | 2026-06-28状态 |
|------|--------|----------------|
| 索引全 | 章鱼覆盖所有资料——八文档+SESSION+其余+外部 | 🟢 基础能力已通 |
| 线索精 | 压缩时留精准线索(路径+章节+关键句+摘要) | 🟡 待优化 |
| 捞回快 | 从线索还原原文——Tantivy毫秒级 | 🟢 可用 |
| **读得透** | **Agent真读、真懂、真引用——否则不推理** | **🔴 2026-06-28发现并立宪** |

### 流水河床哲学

> **context是流水，章鱼是河床。流水过处留沉积物(线索)，河床存完整地质层(原文)。**
> 上下文管理不是控制context里塞多少——是管理：
> 1. 章鱼索引有多全
> 2. 线索有多精准
> 3. 捞回原文有多快
> **4. 读得有多透 ← 2026-06-28补全**

### 强制读取法（2026-06-28用户立宪）

**审验之耻扩大到章鱼资料读取**——看了标题和摘要就以为读了=耻。审验铁律第⑤条：先读章鱼资料再输出，不读标题/摘要=没读。

每轮回答前自检：
```
□ 本轮注射了章鱼搜索结果吗？
□ 我读了每一条的核心内容吗？
□ 我读懂了(不只是物理读到)？
□ 为什么还不满意、还在追问？
□ 我的回复引用了至少一条吗？
```
