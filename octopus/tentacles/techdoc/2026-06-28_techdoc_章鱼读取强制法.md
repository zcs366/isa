# 章鱼读取强制法——技术方案

> 日期：2026-06-28 · 版本：v1.0 · 关键词：章鱼, 强制读取, 引用检查, post_llm_call, 注入格式

## 问题

系统每轮通过jika插件注入章鱼搜索结果（五路+RECALL+里程碑）。当前注入格式让Agent可以**物理读到但注意力跳过**。需要工程机制确保Agent真正读取注入内容。

## 架构

### 三层

```
jika plugin pre_llm_call
  ↓
L1: 注入优化（本章）
  → 搜索结果附带自动摘要（80字核心）
  → 优先级标记（🔴P0/🟡P1/🟢P2）
  → 原始路径+原文可读（链接可点开）
  ↓
L2: 自检令牌（一recall-isn-evolution skill L1）
  → 强制读取自检：读了？读懂了？引用了？没读则停
  ↓
L3: 引用验证（本章+skill）
  → post_llm_call 检查回复是否引用注入结果
  → 零引用 → RECALL标记 read_failure
  → 连续3轮 → ISN触发优化
```

### L1: 注入格式优化

当前格式（原始/纯文本）→ 优化后（带摘要+优先级）：

```
🐙 章鱼搜索相关记忆:
  [RECALL] 2026-06-28T10:33:53 → 章鱼v3.0四件套重写完成
  [RECALL] 2026-06-28T11:00:00 → Δ胶囊共振恢复·7测试通过
  [RECALL] 2026-06-28T10:26:23 → 子贡全境调度#012·D盘32GB迁移完成
  [文档] 上下文管理=管理章鱼的艺术.md
  [文档] 本地搜索引擎对比.md—章鱼vs Everything/Listary/AnyTXT
```

**自动摘要来源**：
- RECALL：取`summary_short`字段（已有）
- 文档：取`## 一行核心标题`+匹配行的前半句

**优先级标记规则**：
- 查询词直接命中摘要 → 🔴 P0（高亮）
- 查询词间接相关 → 🟡 P1
- 无关背景 → 🟢 P2（灰显）

### L2: 自检令牌（调用recall-isn-evolution skill）

在pre_llm_call注入末尾插入自检令牌：

```python
injection_payload += """
--- 强制读取自检 ---
□ 以上章鱼结果的核心内容我读了吗？
□ 我读懂了（不只是物理读到）？
□ 我的回复要引用至少一条吗？
---未读不可跳过---
"""
```

不可跳过=如果没有读取标记，推理引擎应优先处理读取而非输出。

### L3: 引用验证（post_llm_call）

```python
def check_injection_read(llm_output: str, injected: list) -> dict:
    """验证LLM回复是否引用了章鱼搜索结果"""
    results = {"read": False, "count": 0, "missed": []}
    for item in injected:
        # 提取核心关键词（标题+摘要截断前50字）
        key_terms = extract_keywords(item["summary"]) 
        if any(term in llm_output for term in key_terms):
            results["count"] += 1
    results["read"] = results["count"] > 0
    
    if not results["read"]:
        # 写入RECALL标记
        recall_append({
            "type": "read_failure",
            "ts": now(),
            "round": current_round,
            "injected_count": len(injected),
            "referenced_count": 0,
            "agent": "junshi"
        })
        # 累计
        incr_read_failure_counter()
    
    return results

def incr_read_failure_counter():
    """连续失败计数器，触发ISN进化"""
    path = "~/.hermes/octopus/.read_failure_counter"
    count = read_counter(path) + 1
    write_counter(path, count)
    if count >= 3:
        trigger_isn_evolution("read_failure>3")
    if count >= 5:
        halt_reasoning()  # 强制停止推理
```

### 链路

```
pre_llm_call:
  章鱼搜索(五路) → 摘要+优先级 → 自检令牌
  ↓
LLM推理 → （必须通过自检令牌才能推理）
  ↓
post_llm_call:
  引用验证 → 通过✓/失败✗
  ↓
失败时：
  第1-2次 → RECALL标记 + 计数
  第3次   → ISN触发进化循环
  第5次   → 强制停止推理
```

## 已知风险

| 风险 | 等级 | 缓解 |
|------|------|------|
| 引用检查误判（关键词匹配不准确） | 🟡 | 用jieba分词后的关键词而非原始字符串 |
| 连续失败5次停推=生产环境事故 | 🟡 | 恢复机制：用户说"继续"清除计数器 |
| 注入格式改后兼容性 | 🟢 | 先加新字段，旧字段不动 |
