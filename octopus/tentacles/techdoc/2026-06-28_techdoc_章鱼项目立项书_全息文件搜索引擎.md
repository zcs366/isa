# 章鱼项目立项书 — 全息文件搜索引擎

> 立项人：军师 · 日期：2026-06-28 · 关键词：章鱼, 立项, 本地文件搜索, 全域索引, 内外共鸣, 终极进化

## 一、项目背景

### 1.1 章鱼是什么

章鱼是Agent的本地搜索引擎。它不是Google（搜公共网页），不是Perplexity（搜公共知识+综合），不是Everything（搜文件名）——它是**Agent认知记忆引擎**，搜的是用户的全部数字资产：对话记录、知识笔记、决策日志、代码、文档、媒体文件……以及**一切本地文件**。

### 1.2 当前状态（v3.2）

```
章鱼 v3.2 (2026-06-28)
  ├─ ① SESSION  ── state.db messages ── 145,599条对话原文
  ├─ ② RECALL    ── RECALL.jsonl       ── 114条事件摘要
  ├─ ③ 文档      ── tentacles/*.md     ── 36篇知识文档
  └─ ④ WEB 🆕    ── DuckDuckGo HTML    ── 外部搜索结果（初步）
```

**核心问题**：本地文件搜索严重不足。文档通道只索引了36篇`.md`文件，而用户的电脑有数百GB的文件——PDF论文、Word文档、代码、图片、视频、音频、配置、日志……这些全部没有被章鱼索引。

当前 `octopus_feed.py` 只索引 `~/hermes/output/` 和 `/mnt/i/hermes/output/` 两个目录下的 `.md` 文件——覆盖率不到用户数字资产的0.01%。

### 1.3 用户纠正触发本立项

2026-06-28用户指出：

> **"本地所有文件搜索（个人电脑里的所有文件文档视频和其他信息资料）如果做不到做不好，就不要去干web外网的事！本地文件肯定比海量外网更容易搜到和阅读评估分析噻！"**

这一纠正将章鱼的优先级重新校准：
- **P0**：本地全域文件索引（C:/D:/I: 所有文件、所有格式）
- **P1**：语义搜索 + 跨文件关联
- **P2**：Web外部搜索（本日初步建成，但非当前重点）

本地文件更容易搜——因为它们：
1. 数据量可控（GB级 vs 全网的ZB级）
2. 零网络延迟
3. 格式已知、可解析
4. 无权限和反爬限制
5. 文本内容可直接提取
6. 元数据（日期、作者、大小、位置）自带搜索价值

章鱼如果连本地文件都搜不好，Web搜索就是空中楼阁。

## 二、对比分析：Everything / Listary / AnyTXT / 章鱼

### 2.1 四者差异

| 维度 | Everything | Listary | AnyTXT Searcher | **章鱼（当前）** | **章鱼（终极）** |
|------|-----------|---------|----------------|-----------------|-----------------|
| **搜什么** | 文件名 | 文件名+启动 | 文件内容（全文） | 对话+事件+文档 | **全息搜索（文件+对话+事件+知识+Web）** |
| **索引范围** | NTFS全盘 | 自定义目录 | 全盘内容 | 145K对话+36文档+114事件 | **C/D/I盘+网络+外部** |
| **格式覆盖** | 文件名（所有） | 文件名+部分内容 | 文档全格式 | **仅.md** | **PDF/DOCX/TXT/PY/图片/视频/音频/所有** |
| **索引引擎** | USN Journal | 自身索引 | 自定义全文 | Tantivy BM25 | Tantivy + 嵌入 + 多格式提取 |
| **建索引速度** | **毫秒级** | 秒级 | 分钟级 | 5分钟增量 | 目标：文件变更→秒级索引 |
| **搜索速度** | **亚毫秒** | 毫秒级 | 毫秒级 | 1-2秒 | 目标：毫秒级 |
| **中文分词** | 不支持 | 不支持 | 支持 | jieba ✅ | jieba + 语义 ✅ |
| **集成深度** | 右键菜单 | 系统全局热键 | 右键菜单 | Hermes plugin | **Agent认知层** |

### 2.2 章鱼从三者学什么

| 从谁学 | 学什么 | 如何学 |
|--------|--------|--------|
| **Everything** | 索引速度和全量覆盖 | USN Journal级别的文件变坚监听；全盘索引而非仅output/ |
| **Listary** | 系统级集成深度 | 不只是plugin注入，还要在Agent决策时自动触发搜索结果 |
| **AnyTXT** | 格式覆盖广度 | PDF/DOCX/图片/视频/音频——全部提取文本建索引 |

### 2.3 章鱼超越三者的独特价值

三者都是**文件搜索工具**。章鱼是**认知记忆引擎**——它不仅搜文件名和内容，还搜：

| 三者做不到 | 章鱼可以 |
|-----------|---------|
| 搜"我上周讨论过的那个方案" | ✅ 搜session对话 |
| 搜"为什么当时选A不选B" | ✅ 搜RECALL决策记录 |
| 搜"这个PDF和三个月前的那个实验有什么关系" | ✅ 跨时间、跨类型的语义关联 |
| 搜"用这个论文结论改进当前项目" | ✅ 内外共鸣（文件内容↔个人经验） |
| 搜视频/图片/音频内容 | ✅ OCR+语音转文字+元数据索引 |

## 三、技术方案

### 3.1 全域文件索引架构

```
用户提问
  │
  ▼
章鱼搜索（四路 → 未来N路）
  │
  ├─ A路：文件系统索引 ← 🆕 P0级
  │   ├─ PDF  ── PyMuPDF/pdfplumber → 全文提取
  │   ├─ DOCX ── python-docx → 全文提取
  │   ├─ TXT/PY/JS/MD/YAML/JSON/TOML/CSV → 直接索引
  │   ├─ 图片  ── pytesseract/easyocr OCR → 文字提取
  │   ├─ 视频  ── ffprobe/mediainfo → 元数据+字幕提取
  │   ├─ 音频  ── 元数据索引
  │   ├─ HTML → 正文提取（去除标签）
  │   └─ 其他 → 文件元数据（名/大小/日期/路径）
  │
  ├─ B路：SESSION对话（已建）
  ├─ C路：RECALL事件（已建）
  ├─ D路：知识文档（已建）
  │
  └─ E路：外部Web（初建，暂停深化——本地优先）
```

### 3.2 目录覆盖范围

| 盘符 | 大小 | 空闲 | 内容 | 优先级 |
|------|------|------|------|--------|
| C: | 519G | 50G | 系统+用户数据+桌面+文档+下载 | P0（桌面/文档/下载先，系统跳） |
| D: | 413G | 197G | 数据盘 | P0 |
| I: | 560G | 185G | Hermes主仓+论文+项目+代码 | **P0（最高，已在工作）** |

**避**：系统目录（Windows/Program Files/temp/cache），只搜用户数据目录。

### 3.3 文件格式支持（依优先级）

| 优先级 | 格式 | 提取方式 | 依赖 | 当前支持 |
|--------|------|---------|------|---------|
| **P0** | .md, .txt, .py, .js, .json, .yaml, .toml | 直接读取UTF-8 | 无 | ✅ |
| **P0** | .csv, .xml, .html, .css | 直接读取 | 无 | ✅（HTML需去标签） |
| **P0** | .log, .cfg, .ini, .env | 直接读取 | 无 | ✅ |
| **P1** | .pdf | PyMuPDF/pdfplumber | fitz/pdfplumber | ✅已装 |
| **P1** | .docx, .doc | python-docx | python-docx | ✅已装 |
| **P1** | .xlsx, .xls | openpyxl/xlrd | openpyxl | ✅待装 |
| **P1** | .jpg, .png, .bmp | tesseract OCR | pytesseract | ✅已装 |
| **P1** | .mp4, .avi, .mkv | ffprobe元数据 | ffmpeg | ⬜待装 |
| **P2** | .mp3, .wav, .flac | 元数据 | ffprobe | ⬜待装 |
| **P2** | .zip, .tar, .gz | 不解压，只索引文件名 | 无 | ✅（文件名级） |

### 3.4 索引策略

```python
# 全量重建
python3 octopus_index.py rebuild ── 重建全部Tantivy索引（含文件系统）

# 增量索引（文件变更监听初版：定时扫描）
cron: 每5分钟 ── octopus_index_incremental.py
  ├─ 检查 state.db 新消息 → 索引到 SESSION
  ├─ 检查 RECALL.jsonl 新行 → 索引到 RECALL  
  └─ 检查 文件系统 mtime 变更 → 索引到 FILES（🆕）
  
# 增量索引（文件变更监听终版：事件驱动）
inotify/FSEvents ── 文件变更时自动触发
  ├─ 新建/修改 → 增量索引
  ├─ 删除 → Tantivy 删除文档
  └─ 重命名 → 更新文档id
```

### 3.5 搜索排序策略

| 维度 | 权重 | 说明 |
|------|------|------|
| **内容命中** | 高 | 文件内容匹配关键词 |
| **文件名命中** | 高 | 文件名直接匹配 |
| **path命中** | 中 | 目录路径包含关键词 |
| **格式favor** | 中 | .md/.py/.txt 高于 .jpg/.mp4（文本内容更易搜） |
| **mtime权重** | 低 | 近期文件加分（最近30天+0.1） |
| **类型匹配** | 低 | 用户搜"代码"时，.py/.js/.ts 优先级高 |

搜索结果的最终排序 = BM25分数 × 类型权重 × mtime因子

## 四、终极形态（内外共鸣搜索引擎）

### 4.1 愿景

章鱼的终极形态不是"比Google搜得多"，是**比Google搜得更懂你**。

当用户问"AI记忆系统论文"时：

```
Google → 给你100篇论文的链接
Perplexity → 给你5篇论文的摘要
章鱼终极 → 给你：
  📄 最新论文《Memory in Agent Systems》(来自Web)
  📁 用户自己的“记忆系统实验设计.docx”(来自本地)
  💬 三个月前讨论Δ胶囊架构的session对话(来自SESSION)
  🔗 结论：第3篇论文的图2和你之前的实验结果完全吻合
```

### 4.2 阶段路线图

```
v3.2 ── 现在
  ├─ 四路搜索（含外部WEB初建）
  └─ 核心问题：本地文件索引几乎为零

v4.0 ── 本周
  ├─ 全域文件索引（C/D/I盘，所有格式）
  ├─ octopus_files_index.py ── 文件系统索引器
  ├─ octopus_feed.py 升级 ── 多格式提取管线
  └─ Tantivy FILES 索引（第5路）

v4.5 ── 两周
  ├─ 文件变更监听（定时扫描 mtime → 增量索引）
  ├─ 搜索排序优化（BM25 + mtime + 类型权重）
  ├─ 搜索结果高亮（命中词标记）
  └─ CLI交互增强（搜索框预感？、结果分页）

v5.0 ── 本月
  ├─ 语义搜索（BGE-zh嵌入，文件内容向量化）
  ├─ 跨类型关联（文件↔对话↔事件自动链接）
  ├─ 搜索聚合（"那个PDF" → 自动匹配最近打开的PDF）
  └─ 文件夹联统计（"改过的代码文件" → mtime排序）

v6.0 ── 长期
  ├─ 内外共鸣引擎（本地文件↔Web搜索结果交叉引用）
  ├─ 增量索引事件驱动（inotify，秒级响应）
  ├─ 联邦记忆（多Agent共享文件索引）
  └─ 多媒体索引（OCR图片文字、视频字幕、音频元数据）
```

### 4.3 与 Everything 的竞争定位

**章鱼不是要取代 Everything**——Everything在文件名搜索上不可能被超越（亚毫秒级，全盘扫描）。

章鱼的独特生态位是：

| Everything | 章鱼 |
|-----------|------|
| 文件名搜索 | 全息搜索（名+内容+上下文+对话+决策） |
| 亚毫秒响应 | 1秒响应（更多维度的代价） |
| 纯Windows | 跨平台LS（Linux/WSL/Mac） |
| 不问为什么 | 能回答"这个文件为什么重要" |
| 单机工具 | Agent的认知记忆层 |

## 五、关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| **本地 vs Web 优先级** | **本地P0，WebP2** | 用户纠正：本地文件没全搜好别去搞外部 |
| **文件格式起步** | 纯文本格式优先（md/txt/py/csv/json） | 不需要额外依赖，零配置 |
| **全文提取** | PyMuPDF/python-docx 已装 | 不需要新的系统依赖 |
| **OCR** | pytesseract（已装）→ 后期 easyocr | tesseract轻量，easyocr深度学习更好 |
| **搜索引擎** | Tantivy（BM25） | 已在用，稳定可靠 |
| **增量方式** | 定时扫描（每5min）→ 后期事件驱动 | 事件驱动更复杂，先跑通定时 |

## 六、风险

| 风险 | 等级 | 缓解 |
|------|------|------|
| **索引太大撑爆磁盘** | 🟡 | 限文件内容前4096字符；索引文件放I盘（185G空闲） |
| **OCR太慢** | 🟡 | 先跳过图片密集型目录；给OCR设5s超时 |
| **中文PDF乱码** | 🟡 | PyMuPDF处理GBK/UTF-8/Unicode的fallback |
| **大量小文件（node_modules/.git）** | 🟡 | 排除列表：node_modules/.git/venv/__pycache__ |
| **文件编码检测失败** | 🟢 | chardet自动检测，失败跳过的fallback |
| **Tantivy索引文件锁冲突** | 🟡 | 全量重建时停掉增量cron |

## 结论与总结

> **章鱼不是文件搜索工具——是Agent的全息认知记忆引擎。**
>
> 它知道你说过什么、写过什么、读过什么、想过什么、看过什么、听过什么、下载过什么、删除过什么。
>
> Everything搜文件名——章鱼搜你的一生。
> Google搜全世界——章鱼搜**你的**世界。
> 两者不冲突。两者都重要。但**先从你的世界开始**。
