# Self-Harness: Harnesses That Improve Themselves
> 签发人：军师 · 日期：2026-06-28 · 关键词：自演化、Harness工程、验证驱动、提案-验证循环、Terminal-Bench

---

## 一、论文基本信息

- **标题：** Self-Harness: Harnesses That Improve Themselves
- **作者：** Hangfan Zhang, Shao Zhang, Kangcong Li 等（上海人工智能实验室）
- **来源：** arXiv:2606.09498 [cs.CL]
- **核心问题：** LLM Agent 能否**不依赖人类工程师或更强的外部模型**，仅靠自身能力持续改进自己的运行框架（harness）？
- **研究范式：** 本文提出一种**自演化（Self-Harness）** 范式，将 harness 从静态设计转变为持续自改进的活系统。
- **对比基线：** 人类 Harness 工程（静态）、Meta-Harness（依赖更强外部模型）

## 二、核心方法

### 2.1 总体架构（三轮迭代循环）

```
Self-Harness(模型M, 初始harness h₀, 训练集D_in, 保留集D_ho, 
             评估器E, 提案宽度K, 轮次T) → 最终harness h_T
```

每轮包含三个步骤：

#### 阶段①：弱点挖掘（Weakness Mining）
- 在训练集 `D_in` 上运行 Agent，采集完整执行轨迹 + 验证器判定结果
- 将失败轨迹按**验证器标注的失败特征**聚类（verifier-grounded failure signatures）
- 每个失败特征 = (验证器原因, 行为状态, 抽象机制)
- 输出：结构化证据包

#### 阶段②：Harness 提案（Harness Proposal）
- **同一模型**同时扮演执行者和提案者（非外部优化器）
- 生成 K 个**多样化但最小化**的候选编辑
- 每个编辑必须满足：
  - 针对特定失败机制
  - 只修改必要的 harness 表面
  - 保留不相关行为不变
  - 与其他提案显著不同

#### 阶段③：提案验证（Proposal Validation）
- 在**同时训练集和保留集**上回归测试
- **接收规则：** 至少一个集提升，且两个集都不下降
- 拒绝规则：trade-off（一个集提升另一个下降）→ 拒绝
- 兼容的编辑合并为 `hₜ₊₁`

### 2.2 初始 Harness（极简设计）

本文从最简 harness 出发——仅包含 4 条指令（系统提示、引导、验证、失败恢复），无任何模型特定优化。这证明了 Self-Harness 能从极低起点起步。

### 2.3 可编辑表面

系统提示、工具、验证指南、运行时控制策略、子 Agent、技能、记忆源——本文专注于指令级别，但框架通用。

## 三、关键结果

### 3.1 通率提升（三模型跨家族验证）

| 模型 | 分集 | 初始 | Self-Harness | 绝对增益 | 相对增益 |
|------|------|------|-------------|---------|---------|
| **MiniMax M2.5** | 保留集 | 40.5% | **61.9%** | **+21.4pp** | **+53%** |
| | 总体 | 42.2% | 53.9% | +11.7pp | +28% |
| **Qwen3.5-35B-A3B** | 训练集 | 15.1% | 36.0% | +20.9pp | **+138%** |
| | 总体 | 20.3% | 36.7% | +16.4pp | +81% |
| **GLM-5** | 总体 | 46.1% | 57.0% | +10.9pp | +24% |

**关键发现：** 保留集的提升确认了 edits 的**泛化性**——不仅仅是对训练失败模式的过拟合。

### 3.2 典型编辑案例

- **MiniMax M2.5：** 添加"50 次工具调用后重定向"防止死循环；补充内容标签规范
- **Qwen3.5-35B-A3B：** 增加格式约束、终止条件指令、预验证要求
- **GLM-5：** 约束搜索空间、规范化输出格式、增加确认要求

### 3.3 对比基线

- 人类静态 harness 停留原处
- Meta-Harness（GPT-4o 优化 Qwen3.5）：总体 32.8%，低于 Self-Harness 的 36.7%
- 结论：**自演化优于依赖更强外部模型的元优化**

## 四、与 17 层的关联（L10-L10.b: 自进化）

### 核心映射

Self-Harness 精确对应 17 层架构中 **L10（自演化）→ L10.b（自进化）** 的定义：

| 17层概念 | Self-Harness 实现 |
|---------|------------------|
| **L10: 自演化** | Agent 基于自身执行反馈修改 harness |
| **L10.b: 自进化（机制+边界）** | 提案-验证循环（机制）+ 接收规则（边界） |
| **反馈驱动** | 失败轨迹聚类 → 证据包 |
| **安全护栏** | 必须提升至少一个分集且不降低另一个 |

### 具体对应点

1. **Mechanism（机制）：** 三步闭环（弱点挖掘 → 提案 → 验证）是"自进化"的核心机制——不同于外部监督或静态人工设计
2. **Boundary（边界）：** 接收规则（Δheld-in ≥ 0 ∧ Δheld-out ≥ 0）是进化的安全边界——防止 harness 在某一维度退步
3. **Self-contained（自包含）：** 同一模型同时承担执行者、提案者和验证者角色——无外部依赖

### 对 17 层的贡献

- 证明了 L10.b 是**可行且有效的**——三个不同模型家族均获得显著提升
- 为 L10.b 提供了具体的算法模板：聚类失败模式 → 多样化提案 → 双集回归验证
- 验证了"保留集泛化"——这意味着自进化不会陷入灾难性遗忘

## 五、与 Hermes Agent 的关联

| 维度 | Self-Harness 贡献 | Hermes Agent 应用 |
|------|------------------|------------------|
| **技能自改进** | Harness 编辑包含技能/指令优化 | Hermes 的 skills/ 目录可被自审 |
| **失败模式分析** | 验证器标注聚类 | Hermes 可通过 `plur_feedback` 收集失败信号 |
| **提案验证** | 双集回归测试 | Hermes 的 eval 可定义类似"不退化"约束 |
| **保留集泛化** | 编辑不限于过拟合 | 对应 Hermes 中 PLUR 记忆的泛化性要求 |
| **子 Agent 自演化** | 框架通用支持子 Agent | 多 Agent 场景中每个子 Agent 可独立运行 Self-Harness |

## 六、结论与待办

### 结论

1. **Self-Harness 范式成立：** Agent 可完全自主改进自身运行框架，无需人类或更强模型
2. **泛化性验证：** 保留集提升优于观察到的失败模式，说明 edits 学到了可迁移的通用规则
3. **跨模型鲁棒性：** 三种模型家族（Prop + Open + Closed）均获得正向收益
4. **超越 Meta-Harness：** 自演化（36.7%）> 元优化（32.8%）> 静态（20.3%）

### 待办

1. ✅ 理解 Self-Harness 的三阶段循环算法
2. ✅ 梳理接收规则的严格性（双集非退化）
3. ✅ 将失败聚类策略应用到 Hermes 的 PLUR 记忆反馈系统
4. 🔲 实验：在 Hermes 中实现轻量级 Self-Harness 循环（skills/ 指令自动修订）
5. 🔲 探索"提案宽度 K"对收敛质量的影响
6. 🔲 将验证器从确定性扩展到基于模型的模糊评估
