### Agent循环核心（conversation_loop.py · 4,486行）

这是整个Hermes最核心的文件——**一个4486行的函数**，驱动每一轮用户对话：

```python
# conversation_loop.py 核心循环（简化）
def run_conversation(agent, user_message):
    # 1. 构建上下文
    messages = build_messages(agent, user_message)
    tools = get_available_tools(agent)
    
    # 2. 压缩检查（context_compressor）
    if needs_compression(messages):
        messages = compress(messages)  # 2,426行的压缩器
    
    # 3. 调用LLM（流式）
    response = provider.stream_response(messages, tools)
    
    # 4. 处理工具调用
    for tool_call in response.tool_calls:
        # 4a. 安全检查（tool_guardrails）
        if guardrail_blocks(tool_call):
            continue
        
        # 4b. 执行工具
        result = execute_tool(tool_call)
        
        # 4c. post_tool_call钩子
        post_tool_call_hook(result)
    
    # 5. 后处理
    # 5a. 记忆更新
    # 5b. Skill学习
    # 5c. 会话压缩
    # 5d. 后台任务触发
    
    return response
```

### Hermes的设计哲学（来自AGENTS.md）

```yaml
# 1. Prompt缓存是神圣的
"Per-conversation prompt caching is sacred.
 Anything that mutates past context invalidates that cache."

# 2. 核心是窄腰，能力在边缘
"The core is a narrow waist; capability lives at the edges."

# 3. 不要推测性基础设施
"Speculative infrastructure — hooks with no concrete consumer"

# 4. 行为契约优于快照
"Behavior contracts over snapshots"
```

## 三、Hermes该学什么

openLLM不是从零造——是从Hermes中**提取核心能力**，然后加上自递归改进。

### 从Hermes必须继承的

| 能力 | 位置 | 为什么必须继承 |
|:----:|:-----|:-------------|
| **Agent循环** | conversation_loop.py | 这是心脏。4486行的复杂度是生产级必须的 |
| **工具系统** | tools/ (80+个) | 80个工具是核心能力。openLLM不能从零造80个工具 |
| **频道系统** | gateway/platforms/ (20+个) | 跨平台能力是杀手锏。openLLM没有这个 |
| **Skill系统** | agent/skill_*.py | 完整的skill生命周期管理 |
| **记忆系统** | memory_manager + memory_provider | 持久化记忆 |
| **上下文压缩** | context_compressor.py (2426行) | 智能压缩是长期运行的基础 |
| **Cron系统** | cron/ | 定时任务调度 |

### 从Hermes必须抛弃的

| 问题 | 位置 | 为什么必须抛弃 |
|:----:|:-----|:-------------|
| **Prompt缓存神圣** | 全局约束 | 阻止自递归改进——改prompt有成本 |
| **核心窄腰** | 设计原则 | 阻止核心进化——核心不能改 |
| **推测性基础设施禁止** | 贡献规则 | 阻止创新——必须允许LLM尝试新东西 |

**openLLM = Hermes的核心能力 + 自递归改进安全框架**

