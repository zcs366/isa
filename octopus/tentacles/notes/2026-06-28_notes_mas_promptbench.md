# MAS-PromptBench: When Does Prompt Optimization Improve Multi-Agent LLM Systems?

**来源：** arXiv 2606.23664 · Johns Hopkins (Juyang Bai, Laixi Shi) · 2026-06-23  
**标签：** #多智能体 #prompt优化 #MAS #系统提示词

---

## 核心贡献

MAS-PromptBench 是首个系统性评估**系统提示词优化**在多智能体系统（MAS）中何时有效、何时失效的基准。覆盖 4 个框架 × 9 个任务 × 5 种拓扑 × 3 种通信协议 × 4 种团队规模，量化结果为 **+24.0 到 -16.0 个百分点**。

---

## 核心发现

### 1. 结构化协议增益 +4.3pts（最大信号）

通信协议是影响最大的单一因素：

| 协议类型 | 平均增益 |
|---------|---------|
| Freeform（自由文本） | +1.6 |
| Semi-structured（半结构化） | +2.4 |
| **Structured（结构化，JSON 式预定义字段）** | **+4.3** |

**洞察：** 结构化协议让 agent 间交互可控制、可转移，优化器的改进能可靠传播，不被自由对话稀释。

### 2. 任务类型：编码/工具调用 > 推理

| 任务域 | 平均增益 | 最大增益 |
|--------|---------|---------|
| Coding | +3.7 | +18.0 (Sequential APPS) |
| Tool-calling | **+4.3** | +24.0 (Sequential BFCL) |
| Reasoning | +1.3 | +8.0 (Sequential MATH) |

**原因：** 编码/工具调用产生可验证的中间产物（编译、测试、结构化接口），优化收益可累积；推理任务的逻辑步骤高度相关，局部改进易被后续步骤覆盖。

### 3. 团队 > 4 优化转负

| 团队规模 | 平均增益 |
|---------|---------|
| n=2 | +2.4 |
| n=4 | +0.6 |
| **n=8** | **-0.9** |
| **n=10** | **-2.1** |

**关键线：4 人是个分水岭。** 超过 4 个 agent，手递手次数激增，局部 prompt 优化收益在多次传递中消散。Centralized 拓扑最受影响，Decentralized 最抗衰减。

### 4. 拓扑敏感性

| 拓扑 | 平均增益 | 备注 |
|------|---------|------|
| Single Agent | +4.2 | 基线 |
| Independent（投票） | -0.5 | MATH 上 -16.0 |
| Sequential（流水线） | +0.5 | 平稳但偏低 |
| **Decentralized（去中心化）** | **+2.3** | 最鲁棒 |
| Centralized（中心化） | +1.6 | 放大好坏两端 |

---

## 实用建议

1. **先压团队规模到 ≤4**，否则优化很可能负收益
2. **用结构化通信协议**（JSON schema 预定义交互字段），收益直接翻倍
3. **编码/工具调用类任务优先优化**，推理任务收益有限
4. **去中心化拓扑对 prompt 优化最友好**，中心化拓扑需谨慎

---

## 优化器

- **MAS-GEPA**：为 MAS 扩展的 GEPA 优化器，每 agent 独立候选池，轮序优化单 agent 提示词
- **MAS-MIPRO**：消融对比，结果与 MAS-GEPA 一致
- 任务模型：Qwen3.5-9B；反思模型：Qwen3.5-122B
