# Self-Harness: Harnesses That Improve Themselves

**日期：** 2026-06-28  
**来源：** arXiv:2606.09498 (上海人工智能实验室)  
**作者：** Hangfan Zhang, Shao Zhang, Kangcong Li 等  
**标签：** #LLM #agent #自我改进 #harness #闭环

---

## 核心思想

Self-Harness 提出一种新范式：**LLM Agent 自主改进自身运行框架**（系统提示词、工具、验证规则、编排逻辑），完全无需人类工程师或更强的外部模型介入。

不同模型有各自的行为模式、工具使用习惯和错误类型——A 模型的好 harness 对 B 模型可能是次优甚至有害的。人工为每个新模型重新设计 harness 成本越来越高。

---

## 三阶段闭环

### ① 弱点挖掘（Weakness Mining）
- 让 Agent 在现有 harness 下执行任务 → 收集执行轨迹
- 将失败轨迹按验证器锚定的**失败签名**聚类
- 识别出**模型特异的故障模式**（而非孤立错误）

### ② Harness 提案（Harness Proposal）
- **同一模型**作为提案者，针对特定故障机制生成 K 个候选修改
- 约束：最小化改动、不破坏已有行为、避免大规模重写

### ③ 提案验证（Proposal Validation）
- 在 held-in 和 held-out 两个分割上做**回归测试**
- 接受规则：至少一个分割提升，另一个不退化
  ```
  ∆(j)_in ≥ 0, ∆(j)_ho ≥ 0, max(∆(j)_in, ∆(j)_ho) > 0
  ```
- 验证通过的编辑合并为下一版 harness

## 实验结果

**基准测试：** Terminal-Bench-2.0（89 个容器化终端任务）。  
**测试模型：** MiniMax M2.5、Qwen3.5-35B-A3B（MoE）、GLM-5。  
**初始 harness：** 简版 DeepAgent（短系统提示 + 基础文件/Shell 工具）。

| 模型 | 分割 | 初始 | Self-Harness后 | 绝对提升 | 相对提升 |
|------|------|------|----------------|----------|----------|
| MiniMax M2.5 | Held-in | 43.0% | 50.0% | +7.0pp | **+16%** |
| | Held-out | 40.5% | 61.9% | +21.4pp | **+53%** |
| Qwen3.5-35B | Held-in | 15.1% | 36.0% | +20.9pp | **+138%** |
| | Held-out | 23.8% | 38.1% | +14.3pp | **+60%** |
| GLM-5 | Held-in | 47.7% | 57.0% | +9.3pp | **+20%** |
| | Held-out | 42.9% | 57.1% | +14.2pp | **+33%** |

**关键发现：** 改进能够泛化到 held-out 任务（提案者从未见过的任务），证明编辑针对的是可复用的机制而非过拟合。

## 模型特异的 Harness 改动（示例）

- **MiniMax M2.5：** 要求提前创建输出文件、使用正确内容标签、50轮工具调用后重定向 → 避免无休止探索
- **Qwen3.5-35B：** 加入 artifact 保证子 Agent、依赖预检技能、中间件守卫处理工具错误 → 防止失败时删除必要文件
- **GLM-5：** 尽早写出文件、外部计算分阶段审查、持久化环境变量 → 从探索转向实现

## 对 ISA / Octopus 的启示

1. **三阶段闭环可直接复用**：Terminal-Bench → Octopus 工具轨迹，弱点挖掘 + 提案 + 验证构成自进化管线
2. **回归测试防退化**：held-in/held-out 双分割验证机制值得参考——改进不能以破坏已有能力为代价
3. **模型特异性很重要**：不同 backbone（DS/Claude/Gemini）的 harness 应独立演进，而非共用一套
4. **17层 L10 组织的 DAG 天然支持**：每个子 Agent 的 harness 可独立 self-harness 迭代
