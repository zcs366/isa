## 二、核心主张

> "生产环境变更权限不应驻留在非确定性推理过程中。" 

LLM Agent从被动分析者转变为主动操作者后，非确定性推理（LLM输出）直接持有生产凭证 = 严重安全风险。一次幻觉或提示注入就能触发未授权变更。

## 三、方法论细节

### 三步架构

```
Agent Runtime (非可信) → SAB (准入边界) → SEB (执行强制边界) → 基础设施
```

**SAB（Sovereign Assurance Boundary）**：信任网关，发射签名证书Ω
**SEB（Sovereign Execution Broker）**：信任执行边界，本论文核心贡献

### SEB七步验证管线

| 步骤 | 检查项 | 输入 | 失败动作 |
|------|--------|------|---------|
| ① Φsig | 证书签名 | Ω, σ_SAB | 拒绝 |
| ② Φmatch | 请求匹配合约 | req, Ω, C | 拒绝 |
| ③ Φtime | 有效性窗口 | T_valid | 拒绝 |
| ④ Φpolicy | 策略版本 | P_ver, P_active | 拒绝/重新准入 |
| ⑤ Φrev | 撤销检测 | ρ_rev, ρ_active | 故障关闭 |
| ⑥ Φdrift | 状态漂移 | E_admit, St | 拒绝/重新准入 |
| ⑦ Φreplay | 防重放 | cid, nonce, L | 拒绝 |

**正式验证谓词**：V = Φ₍sig₎ ∧ Φ₍match₎ ∧ Φ₍time₎ ∧ Φ₍policy₎ ∧ Φ₍rev₎ ∧ Φ₍drift₎ ∧ Φ₍replay₎ ∧ Scopeable(C, Platform)

### 关键数据

- p50全管线延迟：**7.5ms**（性能可接受）
- K8s令牌：60秒过期
- AWS STS令牌：900秒过期
- 零常设凭证原则

### 执行模型形式化

```
Execute(Ω, req, St, Platform) → D | O
```
其中：Ω=证书, req=执行请求, St=实时状态, Platform=目标平台

## 四、关键引文

1. "An admission certificate is not enforcement unless the target infrastructure mutation paths actively require a broker to verify it."
2. "Zero standing credentials for agent runtimes — all production authority is session-scoped and time-bound."
3. "Non-deterministic reasoning processes should not hold direct credentials to production mutation pathways."
4. "SAB decides whether a proposal *may* become authority at admission time, whereas SEB enforces that authority at the moment of mutation."

## 五、与L4（动作侧隔离）的映射

| SEB机制 | Hermes对应 |
|---------|-----------|
| 零常设凭证 | IO-S cap_policy的零root原则 |
| 执行时动态签发权限 | IO-S cap_check的动态校验 |
| 七步验证管线 | IO-S dispatch + cap_check |
| 防重放+状态漂移检测 | 包拯审计的状态验证 |
| 签名证书Ω | RECALL的_written_by+_checksum签名 |

**SEB本质上就是L4在基础设施层的具体实现**——当前IO-S有cap_check但没有执行身份和实时状态漂移检测，SEB恰好填补这个缺口。

## 六、批评性思考

**优点**：
- 形式化验证谓词完整覆盖7类攻击向量
- 性能可接受（7.5ms p50）
- 明确区分了准入（SAB）和执行（SEB）

**局限**：
- 需要目标基础设施改造才能让SEB成为强制路径
- 依赖假设：break-glass身份在Agent路径之外
- 实时状态监测(St)的及时性未量化
- 跨Broker一致性（Broker Partition威胁）未深入讨论

## 七、交叉关联

- **Contagion Networks (2606.20493)**：评估偏差传染会使SAB的准入判断漂移→SEB的执行时验证作为第二道防线
- **IO-S**：SEB的七步管线可直接作为IO-S cap_check的升级模板
- **包拯审计**：SEB的signed decision和outcome records与审计链同构
