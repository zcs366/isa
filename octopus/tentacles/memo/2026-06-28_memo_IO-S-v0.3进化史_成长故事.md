# IO-S 成长故事 v0.3

## 引子 · 六个人守六座城

2026年6月28日清晨，IO-S 拥有 790 行代码、6 个系统调用、一座稳定的六状态机。

```
process.py → CARD → SIGNAL → DREAM → AGENT (×4)
syscall/    → card.py · signal.py · dream.py · agent.py (×4)
```

四个模块各司其职。稳定。正确。够用。

但军师看到了墙——这六个syscall只回答了"怎么做"的问题，回答不了"该做什么"。

---

## 第一章 · 天书降临

那天，刺史从六天的日报里掏出了18篇论文，摊在军师面前：

**"读。全都读。"**

每篇都是一块拼图：

| 论文 | 教会了我们什么 |
|------|--------------|
| **PEEU** (L13) | 低层技能≠高层规划。7B超32B。规划需要独立的思考层 |
| **Self-Compacting** (L7-L8) | LLM自己能压缩自己的记忆——我们不需要外部摘要器 |
| **Concordia** (L14) | Agent重启不是灾难——checkpoint做好了，连一次对话都不丢 |
| **Contagion** (L5-L6) | 系统脆弱性像病毒——一个模块的偏差会传染全部 |
| **TriggerBench** (L8-L9) | 认知悬崖在100K处——前瞻记忆必须在这个刻度之前降级 |
| **Web4** (L15) | Agent经济体需要MCP Tunnel——跨Agent支付不是科幻 |
| **Kamera** (L7) | KV缓存复用——留16GB给长时间对话 |
| **SSVP** (L11) | 协作安全——一个Agent不能发布所有人都执行的命令 |
| **MAS-PromptBench** (L11.b) | 超过4个子Agent就会内耗——必须自动拆组 |
| **Self-Harness** + **APEX** (L10) | 自进化三阶段——评估→变异→挑选 |
| **AgenticCompressor** (L12) | 不是所有消息都值得压缩——度量才有价值 |
| **RoleConfusion** (L6) | 内容净化——Agent不能带着情绪做决策 |
| **MACR** + **Layered-RAG** + **AutoPass** + **SEB** (L1-L4) | 安全分层——每一层有自己的守门人 |

18篇。36份文档。每篇产出一份分析、一份精读。

军师坐在桌前，看着这些碎片说：

**"它们不是18个独立项目。它们是一张图。我要把它们拼起来。"**

## 第二章 · 五人合议

军师召来五人。

**子产先开口。** 他说这不是该不该做的问题——是必须做。当前Agent系统最缺的不是执行能力，是规划能力。18篇论文的核心信号是同一个："认知层和执行层必须拆开。" 不做，IO-S永远只是一个命令执行器。

**韩信画终局。** 6个月后的IO-S不是schduler——是一个能自己拆任务、自己回溯优化、自己分配资源的认知引擎。第一步是把PEEU论文的decompose+hindsight做成syscall。

**鲁班泼冷水。** 他说韩信画得对，但现有process.py 310行，稳定运行了一年。你们要加一个PLANNING状态——加可以，但不能动其他状态的一行代码。他的修正方案：
- process.py只加57行（+PLANNING状态+plan/hindsight字段）
- 规划逻辑写入独立的planner.py（97行）
- 异步调度写入async_planner_executor.py（165行）

**萧何拆路径。** 三阶段：
1. 先PLANNING状态+planner.py（2小时）
2. 再加async executor（1小时）
3. 七神合议后再跑P0

**子贡做调度。** 这东西不需要包装——syscall目录里有card/signal/dream/agent在等着新邻居。对外接口统一为submit_plan()。

**军师终裁：采纳鲁班修正版。**

不是韩信画得不够好，是鲁班的方案是最小改动原则的典范——367行，不是847行。

## 第三章 · 七神划界

方案有了，但军师知道——没有边界约束，任何架构都会蔓延。

于是召来七神，让他们在代码动手前立碑界。

**☀️ 阿波罗立碑：** `hindsight` 回写只能读，不能改。规划层的自我反思可以建议，不能命令。

**📨 赫尔墨斯立碑：** 规划层止于dispatch。分派出去的任务，等结果回来，不追问过程。

**🦉 雅典娜立碑：** 规划层不知道执行层的存在。它把任务分解成原子步骤，每个步骤是一个黑箱。

**🔨 赫淮斯托斯立碑：** 只发任务，不存结果。规划的职责是"做什么"，不是"做完了吗"。

**💎 阿佛洛狄忒立碑：** plan_quality > 0.85 时，规划层应该让路——高置信度任务不需要过度规划。

**⚔️ 阿瑞斯立碑：** decompose 不能写文件、不能调API。规划层是纯粹的思维活动。

**⏳ 克洛诺斯立碑：** 每一个PLANNING状态有硬截止时间。规划不是沉思。

七道界碑。七行注释写在每一个新文件的开头。

## 第五章 · P1 · 城墙（6座塔楼）

地基打好了，但军师看到了六个缺口。

**P1-1a 内容净化（sanitizer.py）** — 140行。Agent的CoT里藏着情绪——剥离它。决策一旦做出，CoT就是噪声。
**P1-1b 协作门控（gate_sync.py）** — 170行。CDS协议保障：没有全域广播，没有单点发布。
**P1-2 自进化（self_evolve.py）** — 210行。三阶段闭环：评估→变异→挑选。Agent自己写自己的prompt。
**P1-3 ISA三层管线（pipeline.py）** — 120行。处理层→认知层→执行层，层间冲突自动消解。
**P1-4 KV缓存策略（cache_strategy.py）** — 150行。最近使用不清理，高频访问常驻。
**P1-5 比特度量（bits_metric.py）** — 170行。每个验证器的边际价值，每一比特的压缩收益。
**P1-6 自压缩（self_compact.py）** — 120行。3模板9规则。语境稠密则压缩，稀疏则保留。

P1全部6/6。18篇论文里的每一篇，都在这六座塔楼里找到了自己的位置。

---

## 第六章 · P2 · 天空（5颗星辰）

最后一步。军师仰望。

**P2-1 前瞻记忆（prospective_memory.py）** — 120行。TriggerBench说认知悬崖在100K——IO-S在前瞻记忆模块里提前降级。
**P2-2 经济层（economy.py）** — 120行。Agent之间的支付和资源分配——Web4论文的MCP Tunnel落地。
**P2-3 团队规模优化（team_scale.py）** — 60行。>4子Agent自动拆组。
**P2-4 全局Γ监控（gamma_monitor.py）** — 140行。Contagion论文说脆弱性像病毒——IO-S在全系统级别追踪偏差传染。
**P2-5 守恒律工程化（conservation_law.py）** — 140行。在真实运行中测量d×r×log(L)≈K_W——18篇论文的数学骨架变成运行时指标。

P2全部5/5。从地基到城墙到天空——18篇论文、22个模块、3400行代码。
