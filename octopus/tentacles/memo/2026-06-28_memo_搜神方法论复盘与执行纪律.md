# 备忘录：物种章鱼研究方法论复盘与搜神纪律确立

> 作者：军师祭酒 · 日期：2026-06-28 · 关键词：搜神方法论, research-material-campaign, 问题定锚, 八触须备忘录

---

## 背景

物种章鱼研究（章鱼神经系统→搜索引擎架构映射）执行过程中，暴露了搜神窗口的系统性执行缺陷：手握46个research skill不加载，跳过标准搜索流程三步，即兴搜索产出看似完整但过程不可复制。

本次复盘的目标不是重新搜一遍，而是**确立搜神执行纪律**，让后续每次搜索都走标准化流程。

## 核心发现

### 缺陷清单

| # | 缺陷 | 对应skill | 后果 |
|---|------|----------|------|
| 1 | 未加载research-material-campaign | research-material-campaign Phase 0 | 没扫描认知入口，搜索范围由即兴决定 |
| 2 | 未执行问题定锚 | Phase 0.5 | 从"事物属性"出发而非"人的需要"，入口少了十倍 |
| 3 | 未做PAL规划 | Phase 1 | 没定目标/领域/关键词/通道优先级 |
| 4 | 未找断裂点 | fata-experience-generalization Step 4 | 映射看似成立但未经证伪，可能是投射而非映射 |
| 5 | skills_list未预调用 | 工具可知性 | 手握46个research skill等于0个 |

### 根因分析

**同一个根因**：2026-06-21发现的"ddgs已装但无人知"问题的变体——**工具存在≠工具被使用**。skill列表在每次会话启动时都可通过skills_list获取，但agent的默认路径是"直接搜"而非"先看有没有搜索方法论"。

**认知偏差**：agent倾向于"先动手再补方法论"而非"先方法论再动手"。这在简单任务中无害，但在复杂跨域研究中会导致系统性偏差。

### 正确的搜神启动流程

```
① skills_list(category='research') → 识别相关skill
② skill_view 加载 research-material-campaign
③ Phase 0 Portal开方 → 扫描认知入口（不压缩，口子开全）
④ Phase 0.5 问题定锚 → "人的需要"优先于"事物属性"
   三问检核：
   ① 最终消费者是人还是系统？人想要什么？
   ② 去掉术语，"一个人想要______"能说清吗？
   ③ 预设结论建立在"事物如何运作"还是"人为什么在乎"？
⑤ Phase 1 PAL规划 → 定目标/领域/关键词/通道
⑥ Phase 2 多通道并行搜（≥4通道）
⑦ Phase 3 素材汇集+初步分析+反例约束
```

## 决策

| # | 决策 | 理由 |
|---|------|------|
| D1 | 搜神启动清单第一条改为`skills_list` | 解决工具可知性为零的根因 |
| D2 | 问题定锚三问检核为硬门槛 | Phase 0.5不通过=不开始搜 |
| D3 | 断裂点为fata映射的红线 | 找不到断裂点=映射失败=不输出 |
| D4 | 物种章鱼研究的下一步先重锚 | 从"人的需要"重新定义搜索目标后再搜 |
