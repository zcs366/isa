# 上下文管理=管理章鱼的艺术

**关键词**：上下文管理, 章鱼, 无损压缩, 线索, 原文捞回, context window, 注意力, 流水河床

## 两次转折

**第一次转折（2026-06-28 上午）**：32K→1M。策略从"别超"翻转到"别低于30%"。

**第二次转折（2026-06-28 下午）**：废除比例指标。不要刻意填满任何比例。context是工作台，随时可能被一部书撑满。真正的问题不是空间够不够，是**信息太多时注意力稀释**。

## 核心哲学

**context是流水，章鱼是河床。**

- 流水（context window）：来去自由，每轮刷新，容量有限但不是瓶颈
- 河床（章鱼/octopus）：永久沉积，索引全文，容量无限
- 流水过处留沉积物（线索）：文件路径、章节号、关键句、摘要
- 河床存完整地质层（原文）：需要时octopus_search捞回

**上下文管理 ≠ 控制context里塞多少**
**上下文管理 = 管理章鱼索引有多全、线索有多精准、捞回原文有多快**

## 无损压缩

当context被撑满（读一部书、很多材料、长对话），做法是：

```
原文(100KB) → context中留线索(200字) → 章鱼索引全文 → 原文可随时捞回
                │
                ├ 文件路径：~/hermes/output/极大/xxx.md
                ├ 章节号：§3.2 注意力头分类
                ├ 关键句："α≈10是语义压缩基本常数"
                └ 摘要：一句话总结

context腾出空间。信息零丢失。
```

这不是"丢弃"——是**变换表示**。信息从context中的全文，变成章鱼中的索引+线索。随时可逆。

## 与IAT守恒律的关联

守恒律 d×SNR≈α×log₂(N) 的工程翻译：

- N=窗口大小（1M）→ log₂(N)=20 → 容量大
- d=信息模块数 → 增加d必然压缩SNR（注意力质量）
- 解法不是控制d（堆量或减量），是**改变信息的表示形式**
- 原文在context中=d大、SNR低
- 线索在context中+原文在章鱼中=d小、SNR高、信息零损失

**这就是无损压缩的守恒：信息量不变，表示形式变了，注意力质量提升了。**

## 设计原则

1. **不追求比例**：context用多少算多少，不刻意填满或压缩
2. **关注注意力**：信息太多时做无损压缩，不是删信息
3. **线索标准**：每条压缩后的信息必须包含——路径+章节+关键词+摘要
4. **章鱼兜底**：章鱼索引必须覆盖所有处理过的信息，原文可捞回
5. **流水不恋**：context中的信息来去自由，不追求"全部保留"
