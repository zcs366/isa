# 八触须标准强制执行方案 — IDC推演备忘录

> 签发人：军师 (代IDC) · 日期：2026-06-27 · 关键词：IDC, 八触须, 强制执行, IKO, 校验, 标准

## 一、问题正式定义

八触须标准不是"八爪鱼搜索结果的输出标准"——
**它是整个Agent系统所有SA、ZA、Skill系统执行后的输出标准。**

```
当前错误理解:
  SA产出 → 随便写 → 八爪鱼搜 → 搜不出来 → 怪标准

正确理解:
  SA/ZA/Skill产出 → 按八触须标准格式化 → 进入tentacles/
    → 章鱼自动索引 → 任何Agent搜任何话题 → 精准命中
```

只有所有SA的产出都按统一标准输出，章鱼才能精准抓取有效关联信息——**从底层、基础层搭好搜索引擎的基础设施**。

## 二、IDC四问推演

### 问一：这是P0吗？

**是。** 原因：
1. 当前只有tentacles/下的10篇文档合规，output/下数百篇无格式的自由文档全部不可搜
2. 所有SA的产出（ISN注册、Δ胶囊状态、合议记录、实验报告）散落在RECALL内，FTS5搜得到但snippet残缺
3. 章鱼搜索上限由数据质量决定，当前数据质量约20%
4. **根本矛盾**：章鱼引擎修好了（三通道+FTS5+LIKE+多目录），但喂进去的数据是垃圾。修引擎没用，修数据才有用。

### 问二：最简方案是什么？

**IKO作为执行层+质量门，逐篇校验，不通过不归档。**

不给SA增加额外负担——写出自由文本，IKO负责格式化成标准触须文档。SA专注于内容，IKO专注于格式。

### 问三：风险与平衡点

| 风险 | 严重度 | 应对 |
|------|--------|------|
| 强制校验压制写作意愿 | 🟡 中 | IKO做格式化而非SA自己改，SA只需写好内容 |
| IKO成为瓶颈 | 🟡 中 | 先人工后自动，校验脚本半自动化 |
| 旧文档合规改造成本 | 🟢 低 | 已有脚本批量扫描，逐个修复 |
| 标准太细不灵活 | 🟢 低 | 只检3项必检(标题/关键词/##章节)，其余为警告 |
