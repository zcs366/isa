# 上下文管理 × 习惯养成 — 架构设计

**关键词**：上下文管理, 习惯养成, 注意力工程, context window, token预算, 子Agent隔离, 输出验证, 行为反馈, 河床, IAH, IAT

## 问题定义

两件有关但本质不同的事：

**上下文管理（空间问题）**：每个session的context window由五层组成（基岩/记忆/管线/对话/子Agent）。什么进窗口、什么时候退、怎么压缩、怎么不污染——这是信息进出的艺术。目标：context使用率保持30-40%，LLM注意力不被稀释。

**习惯养成（约束力问题）**：信息进了context后，LLM是否执行是概率问题。我们要让"遵守"的概率逼近100%。三级机制：软提醒（文字）→ 信息前置（pre_llm_call塞信息）→ 输出验证（post_llm_call检查执行）。

两者的接口：上下文管理决定"什么进窗口"，习惯养成决定"进了窗口后是否执行"。

## 核心设计

### 五层上下文架构

| 层 | 内容 | token预算 | 生命周期 |
|---|------|:---------:|---------|
| L0 基岩 | Iam+河床+军规+角色 | ≤4000 | 永久 |
| L1 记忆 | MEMORY+USER+WORKING | ≤1500 | 永久但可压缩 |
| L2 管线 | 铁律→统一检索→insight→里程碑→章鱼→卡片 | ≤800 | 每轮刷新 |
| L3 对话 | 用户消息+agent回复+工具结果 | 动态 | 滚动压缩 |
| L4 子Agent | delegate_task上下文 | ≤500 | 任务完成后只留summary |

### 习惯养成三级约束

| 级别 | 机制 | 约束力 |
|------|------|:------:|
| L1 软提醒 | context文字"请先搜session" | 弱 |
| L3 信息前置 | pre_llm_call先把信息塞进context | 强 |
| L4 输出验证 | post_llm_call检查回复是否使用了注入信息 | 最强 |

### L4输出验证闭环

```
注入信息(A-G七层) → LLM生成回复 → post_llm_call验证
                                      │
                    ┌─────────────────┼─────────────────┐
                    ▼                 ▼                 ▼
              未引用insight?     未遵守铁律?       未使用检索?
                    │                 │                 │
                    ▼                 ▼                 ▼
              记录到RECALL        记录到RECALL       记录到RECALL
              type=behavior_check                    │
                    │                                │
                    └────────────────────────────────┘
                                      │
                                      ▼
                          下一轮pre_llm_call注入
                          "⚠️ 上轮你忽略了X"
```

### 与IAH/IAT的理论关联

**IAH**：注意力是有限资源。上下文管理的本质是注意力管理——把重要信息放在最显眼位置，压缩噪音。

**IAT守恒律**：context window的"信息容量"守恒。d×SNR≈α×log₂(N)。增加信息模块(d)必然稀释注意力(SNR)。解法：不是减量，是提纯。
