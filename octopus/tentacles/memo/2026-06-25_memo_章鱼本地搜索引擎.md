# 章鱼本地搜索引擎

> 签发人：军师 · 日期：2026-06-25 · 备忘录 #003

## 一、什么是章鱼

章鱼 = session 工作记忆的本地搜索引擎。

不是成品文档库（那是 wiki），不是记忆卡片系统（那是 jiak），不是不可变时间线（那是 RECALL）。

章鱼管的是 **"我们现在走到哪了"**——session 中产生的讨论、决策、计划、分析、执行记录。

**PAL 管方向（往哪走），章鱼管记忆（走到哪了）。**

## 二、八只触须

两刀分清：对内/对外 × 过去/未来/规则/杂项。

| # | 触须 | 隐喻 | 核心问题 | 覆盖范围 | 触发场景 |
|---|------|------|----------|----------|----------|
| 1 | 备忘录 | 石碑 | 现在什么状态 | 架构说明、系统设计、阶段总结 | "给子贡写个备忘录" |
| 2 | PAL | 路标 | 接下来做什么 | 计划清单、任务分解、优先级 | "做个 PAL" |
| 3 | 研究分析 | 解剖 | 那是什么 | 深度分析、对比研究、资料整理 | "分析一下这个" |
| 4 | 情报简报 | 雷达 | 外面发生什么 | 竞品动态、行业趋势、外部信号 | "搜一下竞品" |
| 5 | 执行报告 | 脚印 | 实际做了什么 | 代码变更、测试结果、产出物清单 | "报告执行结果" |
| 6 | 会议纪要 | 回声 | 讨论了什么 | 七神合议、五人合议、核战队合议、日常讨论 | "记录这次讨论" |
| 7 | 技术文档 | 工具箱 | 怎么用/规则是什么 | **联邦法**、API 文档、配置指南、故障排查 | "写个使用说明" |
| 8 | 决策记录 | 刻痕 | 为什么这样选 | 技术选型、方向决策、经验教训 | "记下为什么选 A" |

## 三、输出标准

### 3.1 文件命名

```
YYYY-MM-DD_{触须}_{标题}.md
```

示例：
```
2026-06-25_memo_章鱼搜索引擎设计.md
2026-06-25_pal_关5工程计划.md
2026-06-25_meeting_七神天启合议.md
2026-06-25_execution_子贡六刀报告.md
2026-06-25_techdoc_联邦法第3号.md
2026-06-25_decision_为什么选MLA不选GQA.md
```

### 3.2 标题规范

- **必须有标题**：第一行 `# 标题`
- **标题要能独立搜索**：不写"备忘录"，写"章鱼搜索引擎设计备忘录"
- **包含关键词**：标题里出现核心术语

### 3.3 关键词设定

每个文档开头必须有 `> 关键词：` 行：

```markdown
# 章鱼本地搜索引擎

> 签发人：军师 · 日期：2026-06-25
> 关键词：章鱼、搜索引擎、八触须、RECALL、jika、Δ胶囊、ISA、session记忆
```

关键词的作用：
- FTS5 全文搜索的命中率
- 跨文档关联（同一关键词的文档自动聚类）
- 章鱼搜索时的摘要生成

### 3.4 结构规范

```markdown
# 标题

> 签发人/作者 · 日期 · 关键词：xxx, xxx, xxx

## 一、背景/问题

## 二、核心内容

## 三、决策/结论

## 四、待办/下一步
```

### 3.5 便于搜索的设计

| 设计 | 为什么 |
|------|--------|
| 标题含关键词 | FTS5 命中率高 |
| 关键词行 | 补充搜索词 |
| 章节标题用 `##` | 结构化，snippet 提取更准 |
| 决策/结论独立章节 | 快速找到"为什么" |
| 待办独立章节 | 快速找到"下一步" |

## 四、与 RECALL、jika、Δ胶囊、ISA 的关系

```
                    ┌─────────────────────────────────────┐
                    │           联邦 Agent 架构            │
                    └─────────────────────────────────────┘

    RECALL                jiak                章鱼               Δ胶囊
    (不可变时间线)        (记忆卡片)          (本地搜索)         (群体记忆)
    ─────────────        ──────────          ──────────        ──────────
    930行/570KB           20张卡片            八触须文档         SQLite+BGE-zh
    只追加不修改          结构化知识          FTS5全文搜索       跨Agent共享
    所有SA共享            单Agent视角         单Agent视角        群体视角
    原始事件流            知识索引            工作记忆           语义向量

    ↓                     ↓                   ↓                 ↓
    "发生了什么"          "我知道什么"         "我做到哪了"       "我们一起经历了什么"
```

### 四者分工

| 系统 | 问什么 | 答什么 | 生命周期 |
|------|--------|--------|----------|
| RECALL | "发生了什么" | 原始事件流（wink/注册/审计） | 永久（不可变） |
| jiak | "我知道什么" | 结构化知识（卡片+笔记） | 长期（可更新） |
| 章鱼 | "我做到哪了" | 工作记忆（讨论/决策/计划） | 中期（活跃→归档） |
| Δ胶囊 | "我们一起经历了什么" | 跨Agent共享状态 | 长期（语义检索） |

### 数据流

```
session 讨论 → 章鱼写入（备忘录/执行报告/...）
                ↓
            RECALL 追加（jiak_note 事件）
                ↓
            jiak 卡片索引（notes 数组）
                ↓
            Δ胶囊消费（梅克尔链+语义向量）
```

章鱼是 **入口**：session 中的工作记忆先写入章鱼 tentacles。
RECALL 是 **时间线**：章鱼写入的同时，jiak_note 事件追加到 RECALL。
jiak 是 **索引**：RECALL 中的 jiak_note 指向具体卡片的 notes 数组。
Δ胶囊是 **群体层**：消费 RECALL + jiak，形成跨 Agent 共享记忆。

### 与 ISA 的关系

```
ISA Brain（认知引擎）
├─ ingest_signal: 从 RECALL 读信号
├─ dream: 发现卡片关联
├─ predict: 预测信号影响
├─ decide: 目标匹配
└─ insight: 写入卡片

章鱼（搜索入口）
├─ search: FTS5 搜 tentacles + session + file
├─ write: 按八触须格式写入
└─ index: 写入即索引
```

ISA Brain 是 **认知层**（思考），章鱼是 **感知层**（搜索）。
Brain 做深度关联，章鱼做快速检索。
两者互补：章鱼找到素材，Brain 分析关联。

## 五、搜索效率

### 5.1 三层搜索

| 层 | 搜什么 | 工具 | 速度 |
|----|--------|------|------|
| 1 | session 对话 | session_search (FTS5) | 快 |
| 2 | 章鱼 tentacles | octopus.py search (FTS5) | 快 |
| 3 | 文件系统 | search_files_fts (FTS5) | 快 |

三层并行搜索，结果合并。

### 5.2 搜索策略

```
用户问 "守恒律"
  → 层1: session 中提到"守恒律"的对话
  → 层2: 章鱼中关于"守恒律"的备忘录/研究分析/决策记录
  → 层3: 文件系统中包含"守恒律"的文件
  → 合并: 按相关性排序，去重，返回 top 10
```

### 5.3 快速定位

| 问法 | 搜章鱼触须 | 搜 session |
|------|-----------|------------|
| "现在什么状态" | 备忘录 | 最近对话 |
| "接下来做什么" | PAL | 最近对话 |
| "为什么这样选" | 决策记录 | 历史对话 |
| "外面发生什么" | 情报简报 | — |
| "实际做了什么" | 执行报告 | 最近对话 |
| "讨论了什么" | 会议纪要 | 历史对话 |
| "规则是什么" | 技术文档(含联邦法) | — |
| "那是什么" | 研究分析 | 历史对话 |

### 5.4 索引优化

- **写入即索引**：FTS5 实时索引，不需要 rebuild
- **关键词行**：补充 FTS5 命中词
- **标题规范化**：包含核心术语
- **年月分片**：archive 按月归档，减少活跃索引大小

## 七、铁律

1. **不是成品文档。** 翻译完的书、写完的论文 → wiki。
2. **session 产生的。** 讨论、分析、决策、进展 → tentacles。
3. **随时可写。** SA 在 session 中随时按格式写。
4. **FTS5 索引。** 写入即索引，立刻可搜。
5. **不删除。** 只追加+归档。
6. **关键词必须。** 每个文档开头必须有关键词行。
7. **标题可搜。** 标题包含核心术语，能独立被搜到。
