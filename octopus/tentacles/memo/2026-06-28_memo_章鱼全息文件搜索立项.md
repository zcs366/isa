# 章鱼全息文件搜索立项备忘录 — 本地优先，全域覆盖

> 签发人：军师 · 日期：2026-06-28 · 关键词：章鱼, 立项, 本地文件搜索, 全域索引, v4.0, 用户纠正

## 一、背景

**章鱼v3.2已建成四路搜索（SESSION+RECALL+文档+外部WEB）。但核心缺陷暴露：本地文件搜索几乎为零。** 文档通道只索引了36篇`.md`文件，用户的C/D/I盘数百GB文件未被覆盖。

用户当场纠正：

> **"本地所有文件搜索（个人电脑里的所有文件文档视频和其他信息资料）如果做不到做不好，就不要去干web外网的事！"**

这个纠正将优先级重新校准：本地全域文件索引是P0，Web搜索暂停深化。立项书已写入 `tentacles/techdoc/2026-06-28_techdoc_章鱼项目立项书_全息文件搜索引擎.md`。

## 二、核心内容

### 2.1 四者对比（Everything / Listary / AnyTXT / 章鱼）

| | Everything | Listary | AnyTXT | 章鱼v3.2 | 章鱼终极 |
|---|-----------|---------|--------|---------|---------|
| 搜什么 | 文件名 | 文件名+启动 | 文件内容 | 对话+事件+文档 | **全息搜索** |
| 格式 | 所有（文件名） | 文件名+部分 | 文档全文 | **仅.md** | **PDF/DOCX/图片/视频/代码/全部** |
| 引擎 | USN Journal | 自身索引 | 自定义 | Tantivy BM25 | Tantivy + 嵌入 |
| 速度 | **亚毫秒** | 毫秒 | 毫秒 | 1-2秒 | 目标毫秒级 |
| 集成 | 右键菜单 | 全局热键 | 右键 | Hermes插件 | **Agent认知层** |

章鱼超越三者的独特价值：不只搜文件名和内容，还搜**对话上下文、决策因果链、跨时间关联**——这才是不可替代的。

### 2.2 本地文件的独特优势

用户指出：本地文件比海量外网**更容易搜、更容易评估、更容易分析**。根本原因：

| 维度 | 本地文件 | 外部Web |
|------|---------|---------|
| 数据量 | GB级 | ZB级 |
| 访问延迟 | 零（本地磁盘） | 秒级（网络） |
| 格式 | 已知、可解析 | 未知、反爬 |
| 权限 | 无限制 | API限额、封禁 |
| 内容提取 | 直接读文本 | 需要解析HTML |
| 价值密度 | 高（你自己选存的文件） | 低（海量噪音） |

**结论：本地文件是章鱼最该先搜好的。Web是锦上添花，不是雪中送炭。**

### 2.3 终极形态

章鱼的终极形态不是"比Google搜得多"，是**比Google搜得更懂你**。六阶段路线图：

```
v3.2（现在）→ v4.0（本周·全域文件索引）→ v4.5（两周·变更监听+排序）
→ v5.0（本月·语义搜索+跨类型关联）→ v6.0（长期·内外共鸣+联邦记忆）
```

## 四、决策/结论

1. **本地文件搜索是章鱼的当务之急**——当前只搜.md文件是严重不足。用户的C/D/I盘数百GB文件应该被索引。
2. **Web搜索停止深化**——已建成但不再花精力优化，直到本地文件搜索达到"可用"（全盘覆盖、秒级响应）。
3. **形式覆盖从纯文本开始**——md/txt/py/csv/json先全量覆盖所有目录。然后PDF/DOCX。最后图片OCR和视频元数据。
4. **索引策略：定时扫描mtime**——每5分钟扫描指定目录，检查文件变更。后期升级为inotify事件驱动。
5. **章鱼不是要取代Everything**——Everything在文件名搜索上不可超越。章鱼的生态位是"全息搜索"：名+内容+上下文+对话+决策。
